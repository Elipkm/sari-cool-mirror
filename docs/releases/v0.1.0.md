# v0.1.0 — Paper Trade Loop

## Achieved

The smallest complete trading loop now works:

`Trade Idea -> Risk Check -> Paper Execution -> Ledger`

- `POST /api/paper-trades` accepts a simple structured trade idea.
- The deterministic risk engine decides whether it is allowed and calculates position size.
- Paper execution applies configured fee and slippage assumptions.
- Approved and rejected decisions are persisted in PostgreSQL.
- `GET /api/paper-trades` returns the ledger.
- No live exchange execution exists.

## Proof

Automated end-to-end test: `PaperTradingEndToEndTest`.

It starts the Spring Boot application, submits a BTC trade over HTTP, passes it through risk sizing, simulates execution, stores the trade, reads the ledger over HTTP and verifies the persisted record.

GitHub Actions run `33256018833` completed successfully before this release report was created. The release workflow runs the same test again before creating tag `v0.1.0`.

## Simple assumptions

- starting paper equity: €5,000
- risk per trade: 0.5%
- max position: 10%
- simulated fee: 0.25%
- simulated slippage: 0.10%
- assets: BTC, ETH, SOL
- no leverage

## Known limitations

The portfolio state is still a fixed bootstrap paper account. Market prices, persistent cash/positions and mark-to-market P/L belong to v0.2.0.
