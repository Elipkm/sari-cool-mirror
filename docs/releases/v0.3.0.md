# v0.3.0 — One Swing Strategy

## Achieved

The paper trader can now create its own deterministic trading decision from daily market history.

The single strategy is intentionally simple:

- **Entry:** price is above the 50-day average and recovers above the 20-day average after a pullback.
- **Exit:** an open position closes when the daily price falls below the 20-day average.
- **Assets:** BTC, ETH and SOL only.
- **Execution:** all entries still pass through the existing hard risk engine; exits close the complete paper position.

Kraken daily OHLC data is accessed through the small `MarketHistoryProvider` boundary. The same `TrendPullbackStrategy` implementation is used by paper trading and backtesting.

## Backtest

`GET /api/strategy/backtest/{asset}` runs a deliberately small historical check with:

- the same strategy rules used by the paper trader;
- 0.25% simulated fee;
- 0.10% simulated slippage per execution;
- buy-and-hold comparison;
- maximum drawdown;
- completed trade count.

This backtest is a sanity check, not evidence that the strategy has a durable market edge. Formal paper validation remains a later milestone.

## Use

Run the strategy once for an asset:

```text
POST /api/strategy/run/BTC
POST /api/strategy/run/ETH
POST /api/strategy/run/SOL
```

The response is simply `BUY`, `EXIT` or `HOLD`, with the reason and any resulting paper trade.

## End-to-end proof

The automated test proves:

```text
Market history
→ TrendPullbackStrategy
→ BUY decision
→ RiskEngine
→ PaperTradingService
→ persisted position + ledger
```

It also calls the HTTP backtest endpoint and verifies that strategy return, buy-and-hold return and drawdown are produced.

## Deliberately not included

No LLM, sentiment analysis, news feed, strategy optimizer, additional indicators, multiple strategies, scheduler, leverage or live execution were added.

That is intentional: one understandable strategy must prove useful before complexity is allowed.
